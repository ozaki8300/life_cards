# Recall Experience Design

## Concept

Recall Mode は、カードを編集したり操作したりする画面ではなく、昔の自分に静かに浸るための体験である。

Recall Mode = 「浸る」。

目的は、カードに保存された情報を効率よく読むことではない。目的は、カードが残された日の空気、温度、気配にもう一度戻ること。ユーザーが過去の自分と再会するための、静かな舞台を整える。

## Experience Principles

### カードが主役

Recall Mode では、カードそのものが体験の中心にある。UI、演出、補助情報は、カードの記憶を引き立てるためにだけ存在する。

### 操作を増やさない

Recall Mode は作業画面ではない。選択肢やボタンを増やしすぎると、ユーザーは記憶ではなく操作に意識を向けてしまう。必要な操作は、開く、少し読み進める、閉じる程度に留める。

### 静寂を恐れない

余白、間、暗さ、無音は欠落ではなく、この体験の一部である。すべてを説明しない。すべてを埋めない。ユーザー自身の記憶が立ち上がる余地を残す。

### AIは前に出ない

AI はユーザーの記憶を代弁する主役ではない。将来的に AI 語りを入れる場合も、感情を押し付けるのではなく、記憶に静かに光を当てる補助役に留める。

### 音楽は自動再生しない

音楽は強い演出であり、記憶の解釈を一気に塗り替える可能性がある。BGM を導入する場合も、ユーザーが自分で再生する手動体験を基本にする。

### 編集・削除・共有は出さない

Recall Mode では、編集、削除、共有、QR などの管理操作を表示しない。カードを管理する時間と、カードに浸る時間を分ける。

## Architecture

Recall Mode の責務は `src/components/cards/recall/` 配下に閉じる。

`CardDetailModal` は Recall Mode を開く、閉じるための導線だけを持つ。Recall Mode の表示内容、演出、舞台文生成、Back Memo の見せ方などを `CardDetailModal` に混ぜない。

Reencounter Engine とは分離する。Reencounter Engine は「どのカードと再会するか」を扱い、Recall Mode は「再会したカードにどう浸るか」を扱う。

DB / Supabase 変更は慎重に行う。Recall Mode はまず既存カード情報から体験を作る。天気、場所、音楽、AI 語りなどを追加する場合も、永続化の必要性、プライバシー、ユーザー制御を確認してから設計する。

## Roadmap

### v0: Existing Card Overlay

既存カード情報だけで静かな全画面 overlay を作る。カード画像、Front、Comment、作成日由来の舞台文、Back Memo への控えめな導線を表示する。外部 API、DB 変更、AI 語り、音楽再生は入れない。

### v1: Stage Metadata

天気、場所、日付、季節などの舞台情報を扱う。ただし、位置情報取得や外部 API 連携はユーザーの同意と明確な価値がある場合に限る。

### v2: Manual Quiet BGM

静かな BGM を手動再生で導入する。自動再生はしない。Spotify などの連携を入れる場合も、音楽が主役にならないようにする。

### v3: AI Narration

AI 語りを導入する。AI は感動を演出する存在ではなく、カードの記憶をそっと補助する存在として設計する。語りすぎないこと、断定しすぎないことを原則にする。

### v4: Reflection Mode

単一カードの回想を超えて、人生全体を振り返る Reflection Mode へ拡張する。複数カードのつながり、時期、変化、テーマを静かに見つめる体験を目指す。

## Non-goals

Recall Mode は SNS 化しない。反応、公開、拡散、評価のための画面にしない。

ゲーム化しすぎない。達成、報酬、連続記録、派手な演出によって、記憶に浸る体験を邪魔しない。

AI に感動を押し付けさせない。ユーザーの記憶を、AI が勝手に物語化しすぎない。

Spotify を主役にしない。音楽は記憶を支える要素であり、Recall Mode の中心はあくまでカードとユーザー自身の時間である。
